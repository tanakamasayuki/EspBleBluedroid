# CompileSmoke

> 日本語版: [README.ja.md](README.ja.md)
> EspBle differences: [DIFFERENCES_FROM_ESPBLE.md](../DIFFERENCES_FROM_ESPBLE.md)

Minimal build-check sketch. It includes `EspBleBluedroid.h`, touches the common GAP API surface, and prints the library version — without initializing the Bluetooth stack. Use it to confirm the library compiles and links for your board before trying the functional examples.

## Hardware

- 1 × original ESP32 (an ESP32 SoC with Bluetooth Classic, built with the Arduino-ESP32 Bluedroid backend); no peer required

## What it does

- Configures both advertising payloads (name, service UUID, service data, appearance, Tx Power) without starting advertising
- Calls the value-type `EspBleScanResult` accessors so their signatures stay in the build
- Constructs `EspBluedroidSppSerial` and reports `connected()`
- Prints the EspBleBluedroid library version to Serial once at startup

## Key APIs

- `ESPBLEBLUEDROID_VERSION_STR` — library version string defined in `espblebluedroid_version.h`, generated by `tools/bump_version.py`
- `advertising().data()` / `scanResponse()` — the two independent legacy payloads
- `EspBluedroidSppSerial` — Bluetooth Classic SPP as an Arduino `Stream`

## Building

```sh
arduino-cli compile --profile esp32 examples/CompileSmoke
```

## Differences from EspBle

| | EspBle | EspBleBluedroid |
|---|---|---|
| Version macro | `ESPBLE_VERSION_STR` (`espble_version.h`) | `ESPBLEBLUEDROID_VERSION_STR` (`espblebluedroid_version.h`) |
| `sketch.yaml` profiles | `esp32s3` (default), `esp32c3`, `esp32c6`, `esp32h2`, `esp32p4` | `esp32` only |
| Extra API touched | — | `EspBluedroidSppSerial` (Bluetooth Classic) |

**Why:** the two libraries version independently, so each carries its own macro and header name. And EspBleBluedroid targets the original ESP32 exclusively — it is the only ESP32 family member with Bluetooth Classic, which is the whole reason this library exists next to EspBle. The S3/C3/C6/H2/P4 profiles are therefore absent from every `sketch.yaml` here.

**How to port:** replace `ESPBLE_VERSION_STR` with `ESPBLEBLUEDROID_VERSION_STR` and compile with `--profile esp32`.

## Expected Serial output

```
EspBleBluedroid 0.1.0
SPP Serial connected=0
```
